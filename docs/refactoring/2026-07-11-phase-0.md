## 2. 本批重构内容

### 2.1 纠正 core 依赖方向

原问题：`core/tenant.py` 为获得 `DEFAULT_USER_ID` 和 `DEFAULT_NAMESPACE`，反向 import `services/retrieval/metadata.py`。这使 core 依赖业务 service，后续无法建立可靠的分层门禁。

解决方案：

- tenant 默认值归属 `core/tenant.py`。
- retrieval metadata 从 core import 并继续 re-export，保持旧调用方兼容。
- 新增 AST architecture test，阻止 core 再次 import api/services。

### 2.2 修复 User Profile namespace 串数据

原问题：画像路径是 `user_profiles/{user_id}.json`，namespace 只出现在返回值中，没有参与持久化 key。同一个 user 在不同 namespace 下会读取和覆盖同一份画像。

新路径：

```text
user_profiles/{encoded_user_id}/{encoded_namespace}.json
```

路径段使用 URL percent encoding。原因是 tenant 正则允许冒号，而冒号不能作为 Windows 文件名字符；只依靠 tenant 校验仍不足以生成跨平台路径。

兼容策略：

- 优先读取新路径。
- 旧 `user_profiles/{user_id}.json` 只允许默认 `tech_docs` namespace 回退读取。
- 非默认 namespace 不读取旧文件，因为旧文件没有 namespace 证据，无法安全判断归属。
- 后续更新写入新路径，旧文件暂不自动删除，保留回滚窗口。

## 3. 实际遇到的问题

### 问题 A：旧测试固化了不安全行为

原测试在 `tenant-docs` namespace 下直接创建 `user-a.json` 并期望读取成功。这等于把“任意 namespace 都读同一旧文件”当成正确行为。

处理：测试改为写入新 namespace 路径；另加 legacy 测试，明确旧文件只对默认 namespace 可见。

### 问题 B：tenant 合法字符不等于文件名合法字符

`TENANT_ID_PATTERN` 允许 `:`，但 Windows 文件名不允许。若只改成 `{user_id}/{namespace}.json`，带冒号的合法 tenant 仍会在 Windows 失败。

处理：持久化 adapter 对每个路径段做 percent encoding，并增加 `user:a / docs:private` 回归测试。

### 问题 C：Conda 可用但未注入当前 PowerShell PATH

直接运行 `pytest/ruff/mypy` 会提示命令不存在。

处理：读取 Conda 环境注册文件，直接调用 `agent` 环境的 Python 执行 `-m pytest/-m ruff/-m mypy`。这比在每个非交互子进程中依赖 `conda activate` 更稳定。
